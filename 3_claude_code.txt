Operate Claude Code Across a Real Repository

Problem Statement
Rather than using Claude Code casually, operate it deliberately across a real (or realistic sample) repository: correct CLAUDE.md hierarchy, custom commands, and both interactive and headless usage.

What This Proves You Can Do
Configure the CLAUDE.md hierarchy correctly across user, project, and directory scope
Use Claude Code's core components — Rules, Skills, Commands, Agents, Agent Memory — deliberately, not by accident
Operate Claude Code in headless and streaming mode, not just interactively
Setup
Have a real or sample repository and the Claude Code CLI installed
Build Steps
Initialize the repository for Claude Code and configure settings.json
Create a project-level CLAUDE.md, then a directory-level CLAUDE.md for one subfolder with different local conventions — confirm both apply where expected
Create a custom slash command for a task you'd otherwise repeat manually (e.g. "summarize recent changes")
Run a task in headless mode (-p) and capture the output programmatically, as you would inside a script or pipeline
Use /memory (or the equivalent) to confirm which configuration files are actually loaded in a session, and resolve any mismatch from what you expected
