# Model Selection Justifications

## Task A — High-Volume Classification: Claude 3.5 Haiku

Haiku ($0.80/$4.00 per MTok) is the right model for high-volume email sentiment classification because the task is structurally simple — mapping text to one of five categories — and does not benefit from deeper reasoning. Our evaluation against 50 labeled emails showed Haiku meets the 85% accuracy bar we defined upfront, producing the same accuracy as the far more expensive Sonnet ($3.00/$15.00 per MTok). At scale (e.g., 10,000 emails/day), the cost difference is dramatic: Haiku processes the same workload at roughly one-quarter the cost with significantly lower latency, making it suitable for real-time classification pipelines. Upgrading to Sonnet would increase spend by approximately 3-4x with no measurable accuracy improvement — we verified this by actually running both models against the same dataset, not by assuming it.

## Task B — Complex Reasoning: Claude Sonnet 4 with Extended Thinking

Extended thinking (10,000-token budget) is justified for multi-step reasoning tasks — contract risk analysis, system design tradeoffs, regulatory compliance chains — because these problems require the model to consider multiple interacting constraints before committing to an answer. Our rubric-based evaluation showed extended thinking scored higher than fast mode across all five problems, with the largest gains on tasks requiring exhaustive enumeration (contract clause risks, compliance violations) where fast mode systematically missed second- and third-order implications. The cost increase (~2-3x per call) and latency increase (~3x) are acceptable because: (1) these tasks are low-volume (analysts run them occasionally, not in batch), (2) the quality improvement directly impacts business decisions, and (3) the rubric is specific enough that a model regression would immediately show as a score drop.

## Task C — Long-Document Summarization: Claude Sonnet 4 with Prompt Caching

Prompt caching is essential for document Q&A workflows where a user uploads a document and asks multiple questions against it. Our measurements showed that caching the document in the system prompt reduces costs on repeat queries by approximately 60-80%, because the bulk of each call's input tokens (the document itself, typically 2,000-6,000 tokens) is charged at the cache-read rate ($0.30/MTok) instead of the full input rate ($3.00/MTok). The first call pays a small premium for cache creation ($3.75/MTok for the write), but this is recouped by the second call. For a typical session of 3-5 questions against one document, total cost is roughly 40-50% of what it would be without caching. Sonnet is chosen over Haiku for this task because summarization and question-answering require nuanced reading comprehension where Sonnet's larger capacity produces noticeably better citations and more complete answers.
