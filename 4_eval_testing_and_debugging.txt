Diagnose and Fix a Deliberately Broken Claude Application

Problem Statement
Take a working Claude integration and deliberately break it in a way that isn't obvious from the error message alone — then diagnose it using trace analysis before touching a fix. The exam tests whether you can correctly isolate integration-layer bugs from model-output problems, not whether you can fix things by trial and error.

What This Proves You Can Do
Identify and classify error types in a Claude application
Select an appropriate recovery strategy per error type
Use trace analysis to identify the actual failure mode
Correctly separate integration-layer bugs from model-output problems
Setup
Take any working integration you've already built (Domain 1 or 2's assignment works well)
Build Steps
Introduce one integration-layer bug (e.g. a malformed request, a dropped field, an off-by-one in pagination) without changing the prompt
Introduce one separate model-output problem (e.g. an ambiguous prompt that produces inconsistent formatting) without touching the integration code
Before looking at either one again, write down your hypothesis for each failure based on the symptom alone
Use logging/trace output to confirm or reject each hypothesis — do not fix anything until you've isolated the actual cause
Fix each issue using the fix appropriate to its layer — a code fix for the integration bug, a prompt fix for the model-output problem
